Avero's packages are versioned together with [Changesets](https://github.com/changesets/changesets).
Every pull request that touches a published package adds a changeset describing the change and its
bump, and the release collects them into each package's `CHANGELOG.md`.

## Release status

Avero is at **1.0.0**, published to public npm under the `@averoui` scope with npm provenance. The
five published packages are versioned together, so `@averoui/react`, `@averoui/tokens`, `@averoui/font`,
`@averoui/charts` and `@averoui/editor` always share a version number.

Each package's full history lives in its own `CHANGELOG.md`, generated from the changesets that went
into each release.

## What counts as which bump

The five published packages — `@averoui/tokens`, `@averoui/react`, `@averoui/font`, `@averoui/charts` and
`@averoui/editor` — are **linked**, so they move to the same version together. A consumer can
therefore match versions across packages without a compatibility table.

**Major — breaking.**

- Removing or renaming a component, prop, variant, token or CSS variable.
- Changing a default value in a way that alters what gets rendered.
- Raising a peer dependency floor (React, Tailwind, Radix, `lucide-react`).
- Reordering the z-index layers, or changing what a `data-*` attribute means.

**Minor — additive.**

- New components, blocks, props, variants or tokens.
- New dictionary entries, and new locales.
- Relaxing a type so more input is accepted.

**Patch.**

- Bug fixes and visual corrections that restore the documented behaviour.
- Accessibility fixes that do not change the API.
- Dependency bumps with no API effect.

Because Avero's output is CSS classes as much as it is markup, the class list a component emits is
part of its contract: a change that makes a documented override stop applying is breaking even if
the props are untouched.

## Adding a changeset

```bash
pnpm changeset
```

Pick the packages, pick the bump, and write the summary in the past-tense voice used above — it goes
into the changelog verbatim, so it is written for a consumer, not for a reviewer. A PR that changes a
published package without a changeset is incomplete.
