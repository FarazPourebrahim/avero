## Two components

`ReportAction` is the control itself. The same action appears in several places in different
shapes, so it is one component with a `variant` rather than three near-copies:

| Variant | Where                                  | Look                              |
| ------- | -------------------------------------- | --------------------------------- |
| `mini`  | Under a showcase card                  | 11px slate text, warning triangle |
| `text`  | Under an article or course description | 14px gray text, flag              |
| `soft`  | Inside a report panel on a detail page | Tinted rose button, shield        |

`ReportCard` is the panel that wraps the `soft` variant: a title, a line of explanation, and the
button at the end of the row.

## Usage

```tsx
<ReportCard onReport={() => openReportDialog(courseId)} />

<ShowcaseCard title="…" report={<ReportAction onReport={() => openReportDialog(itemId)} />} />
```

`onReport` is the whole contract — the block never opens a dialog, posts a form or shows a
confirmation of its own, because what "reporting" means belongs to the application.

## Anatomy

| Part   | Slot                        | Notes                                     |
| ------ | --------------------------- | ----------------------------------------- |
| Action | `data-slot="report-action"` | A `<button>` in all three variants        |
| Panel  | `data-slot="report-card"`   | A `Card` holding the title and the action |

## Accessibility

Every variant has real text, taken from the `report` dictionary string, so the control is named on
every device. An icon with only a `title` attribute may not be announced by assistive technology
and never reaches a touch user.

## Do and don't

- **Do** confirm the report in your own UI — the button fires immediately.
- **Don't** hide the control behind a hover state; it is the only way to flag abuse.
