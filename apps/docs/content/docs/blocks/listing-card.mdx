## Composition

The card is built only from Avero components — `Card`, `Image`, `Chip`, `Avatar`, `PriceTag` and
`MetaItem` — so a change to any of them flows through every listing automatically:

- the surface is `Card variant="glass" padding="none"`, matching the reference's
  `bg-[var(--bg-card)]` card that turns solid white on hover;
- the category uses `Chip variant="category"`;
- the price uses `PriceTag variant="inline"`, which renders "از ۲۰٬۰۰۰٬۰۰۰ تومان".

## Excerpt handling

The reference stores excerpts as HTML and renders the tags as visible text, so a card literally
shows `<p>…` (defect R-08). `ListingCard` runs the excerpt through `stripHtml` instead
(deviation V-03), which removes markup, decodes basic entities and collapses whitespace:

```tsx
import { stripHtml } from "@avero/react";

stripHtml("<p>انواع طراحی سایت</p>"); // "انواع طراحی سایت"
```

To _render_ stored HTML rather than flatten it, use [RichContent](../components/rich-content),
which sanitizes it.

## Accessibility

- The whole card is a single link named by `title`, so the accessible name never becomes a wall of
  concatenated text.
- The reference nests a `div role="link"` for the author **inside** the card's own link (defect
  R-10). A nested link is invalid, so the author row here is plain content and the card stays one
  link target (deviation V-04). The visuals are unchanged.
- The cover image is decorative (`alt=""`): its meaning is already carried by the title.

## Do and don't

- **Do** pass `excerpt` exactly as stored; stripping is handled for you.
- **Don't** place another link or button inside the card — the surface is already one link.
