## Anatomy

| Part       | Slot                              | Notes                                              |
| ---------- | --------------------------------- | -------------------------------------------------- |
| Root       | `data-slot="provider-card"`       | A `Card` surface with `space-y-6`                  |
| Name       | `data-slot="provider-card-name"`  | An `h4` under the eyebrow                          |
| Statistics | `data-slot="provider-card-stats"` | Two-column grid of `MiniStat`s; omitted when empty |

## Usage

```tsx
<ProviderCard
  name="نگار رضایی"
  headline="مدرس طراحی رابط کاربری"
  image="/instructors/negar.jpg"
  stats={[
    { label: "تعداد دوره‌ها", value: "3" },
    { label: "امتیاز شرکت‌کنندگان", value: <Rating value={4.8} size="sm" /> },
  ]}
  profileHref="/instructors/negar"
/>
```

The eyebrow and the profile link fall back to the `serviceProvider` and `viewProfile` dictionary
strings, so both follow the active locale without being passed.

## Composition

Built from `Card` (`surface`, `xs` elevation), `Avatar` (64px with a two-pixel indigo ring),
`Eyebrow`, `MiniStat` and an outlined `Button` rendered `asChild` as a link.

Statistics are deliberately untyped beyond `label` and `value`: a rating stat is a filled star
beside a two-decimal score, which is `Rating` rather than a number, and the same slot takes plain
counts.

## Accessibility

- The name is a real `h4`, so the card joins the page outline beside the other sidebar panels.
- The profile link is a link, not a button — it navigates.
- `Rating` exposes itself as one image labelled with its score, so the score is announced as a
  rating rather than as a bare number.

## Do and don't

- **Do** keep statistics to an even number — the grid is two columns wide.
- **Don't** put the whole card in a link; only the profile call to action navigates.
