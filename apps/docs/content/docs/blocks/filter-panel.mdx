## Anatomy

| Part     | Slot                                | Notes                              |
| -------- | ----------------------------------- | ---------------------------------- |
| Root     | `data-slot="filter-panel"`          | A `<section>` named by its heading |
| Controls | `data-slot="filter-panel-controls"` | The stack, in a 12px rhythm        |

## Usage

The controls are children, not props — which filters a listing needs is the application's
decision, and each control already carries its own styling:

```tsx
<FilterPanel>
  <Input aria-label="جستجو" placeholder="جستجو..." value={query} onChange={…} />
  <Select value={category} onValueChange={setCategory}>
    <SelectTrigger aria-label="دسته‌بندی">
      <SelectValue placeholder="همه دسته‌ها" />
    </SelectTrigger>
    <SelectContent>…</SelectContent>
  </Select>
  <Select value={sort} onValueChange={setSort}>
    <SelectTrigger aria-label="مرتب‌سازی">
      <SelectValue />
    </SelectTrigger>
    <SelectContent>…</SelectContent>
  </Select>
</FilterPanel>
```

The controls are the panel's own: a search [`Input`](../components/input) and one
[`Select`](../components/select) per filter, so every trigger carries the same 12px radius and the
same listbox. Swap in a [`Combobox`](../components/combobox) where a filter has enough options to
need searching.

## Accessibility

- The panel's `<section>` is named by its heading through `aria-labelledby`, so it is announced as
  a region.
- Every control needs its own accessible name. The examples here use `aria-label`, because a
  visible `<label>` would change the layout.

## Do and don't

- **Do** apply filters as they change; the panel has no submit button.
- **Don't** nest a `<form>` inside unless a submit actually exists — a form with no submit
  control traps keyboard users who press Enter.
