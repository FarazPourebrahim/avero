## Anatomy

| Part       | Slot                                     | Notes                                  |
| ---------- | ---------------------------------------- | -------------------------------------- |
| Root       | `data-slot="dashboard-shell"`            | Vertical rhythm wrapper                |
| Container  | `data-slot="container"`                  | `main` landmark, tighter phone gutters |
| Sidebar    | `data-slot="dashboard-shell-sidebar"`    | One third, from `lg`                   |
| Mobile bar | `data-slot="dashboard-shell-mobile-bar"` | Card shown below `lg`                  |
| Content    | `data-slot="dashboard-shell-content"`    | Two thirds, white card, `min-w-0`      |

## Right-to-left

The grid mirrors with the document direction, so the sidebar sits at the inline start either way.

## Composition

- Put [SidebarNav](./sidebar-nav) and the greeting in `sidebar`; it only shows from `lg`.
- `mobileBar` replaces it below `lg` — pair it with a [Drawer](./drawer) trigger for the full menu.
- The content card carries `min-w-0`, so wide tables and charts inside it scroll instead of
  stretching the grid.

## Accessibility

- The container is the `main` landmark; the dashboard page should not add another.
- Name the sidebar navigation (`aria-label`), because the drawer contains a second copy of it.

## Do and don't

- **Do** keep the same navigation items in the sidebar and the drawer.
- **Don't** wrap the shell in another `Container`; it provides its own.
