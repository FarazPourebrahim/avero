| ----------- | ------------------------------- | ------------------------------------------------------ |
| Viewport    | `data-slot="toast-viewport"`    | Fixed region on `--z-toast`; `role="region"`           |
| Toast       | `data-slot="toast"`             | `data-tone`, `data-paused`, `data-state`, `data-swipe` |
| Icon        | `data-slot="toast-icon"`        | The tone's icon, or a spinner for `loading`            |
| Title       | `data-slot="toast-title"`       | Bold headline                                          |
| Description | `data-slot="toast-description"` | The message                                            |
| Action      | `data-slot="toast-action"`      | Optional button; clicking it also closes the toast     |
| Close       | `data-slot="toast-close"`       | Corner button at the inline end                        |
| Progress    | `data-slot="toast-progress"`    | Drains over the duration; hidden with reduced motion   |

## Setup

Render one `ToastProvider` near the root, inside `AveroProvider`. Anything inside it can call
`useToast`.

```tsx
<AveroProvider locale="fa-IR">
  <ToastProvider>
    <App />
  </ToastProvider>
</AveroProvider>
```

## Usage

```tsx
const { toast, update, dismiss, promise } = useToast();

toast({ tone: "success", title: "ذخیره شد", description: "تغییرات پروفایل ذخیره شد." });

// A loading toast that becomes the result in place.
const id = toast({ tone: "loading", title: "در حال ارسال…" });
update(id, { tone: "success", title: "پیام ارسال شد" });

// The same, driven by a promise.
promise(sendMessage(), {
  loading: { title: "در حال ارسال…" },
  success: { title: "پیام ارسال شد" },
  error: (error) => ({ title: "ارسال نشد", description: describe(error) }),
});

dismiss(id);
```

- **Tones:** `info` (default), `success`, `warning`, `danger` and `loading`. A `loading` toast shows
  a spinner in the brand colour and stays open until it is updated or dismissed.
- **Duration:** 5 seconds by default; set it per toast or on the provider. `Infinity` keeps a toast
  open until it is closed, and is the default for `loading`.
- **Updating:** `update(id, options)` changes a toast's tone, message, action or duration where it
  stands. Options you leave out keep their values, except `duration`, which falls back to the new
  tone's default — so a `loading` toast updated to `success` starts the provider's timer. An update
  is announced again. Updating a toast that has already closed does nothing.
- **Promises:** `promise(pending, { loading, success, error })` shows `loading` straight away and
  turns into a `success` or `danger` toast when `pending` settles; `success` and `error` can be
  functions of the value or the error. It returns `pending` itself, so a rejection still reaches
  your own code.
- **Stacking:** new toasts join the bottom of the stack. With more than `limit` (3 by default), the
  oldest closes.
- **Pause on hover:** the timer and the progress bar pause while a toast is hovered or focused, and
  while the window is in the background.

## Mobile

Up to 480px wide, toasts span the screen with a small gutter. Wider screens show them in a 24rem
column at the bottom of the inline end. Swipe a toast toward that edge to dismiss it.

## Examples

### Actions and lifetime

`action` puts one button beside the message and closes the toast when it is used; its `altText`
tells a screen reader user how to do the same thing without it. `duration: Infinity` keeps a toast
until it is dismissed, and the provider's `limit` caps how many stack at once.

<ComponentPreview name="toast/action" />

### Loading, then the result

Use a `loading` toast for work the user started and is waiting on, such as sending a message, and
turn it into the outcome with `update` or `promise` rather than closing it and opening another. The
result replaces the spinner in the same place, without sliding in again.

## Right-to-left

The column sits at the bottom left in Persian and the bottom right in English. The swipe direction,
the close button and the progress bar, which drains toward the inline start, all follow the
`AveroProvider` direction.

## Composition

- Show a toast from a mutation's `onSuccess` or `onError`, with the `messageKey` of an API error
  translated as the description.
- Offer **Undo** as an `action` after a reversible delete, and describe another way to undo it in
  `altText`.
- For a message that must stay until the problem is fixed, use an [Alert](./alert).

## Accessibility

| Key                                                | Action                                 |
| -------------------------------------------------- | -------------------------------------- |
| <kbd>F8</kbd>                                      | Moves focus to the toast region        |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves between toasts and their buttons |
| <kbd>Escape</kbd>                                  | Closes the focused toast               |

- Toasts are announced by a live region: `danger` toasts assertively, the others — `loading`
  included — politely. An updated toast is announced again, with its new politeness, so the outcome
  of a `loading` toast is heard.
- Focus is never moved to a toast, so reading or typing isn't interrupted.
- Anything a toast action does must also be possible elsewhere in the page, since a toast can close
  before a keyboard or screen reader user reaches it. `altText` tells screen reader users where.
- The region is labelled from the dictionary's `toastRegion` entry.

## Do and don't

- **Do** keep toasts to one short sentence about something that just happened.
- **Don't** put errors that block the task in a toast; show them next to the form or field.
- **Do** turn a `loading` toast into its result with `update` or `promise`; **don't** dismiss it and
  open a second toast, which reads as two separate events.
