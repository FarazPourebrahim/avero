## Anatomy

| Part  | Slot                       | Notes                                                      |
| ----- | -------------------------- | ---------------------------------------------------------- |
| Part  | Slot                       | Notes                                                      |
| ----- | -------------------------- | ---------------------------------------------------------- |
| Root  | `data-slot="spinner"`      | A `<span>`; `aria-hidden` unless it is labelled            |
| Parts | `data-slot="spinner-part"` | `dots`, `bars` and `spokes` only: the dots, bars or spokes |

`ring`, `track` and `glow` have no inner structure: `ring` is a border with one transparent side,
`track` is a coloured arc on a faint full circle, and `glow` is the `glow-ring` utility. `dots`,
`bars` and `spokes` are built from parts sized in percentages of the root, so all six follow the
same size scale. The root also carries `data-variant`.

## Examples

### Variants

`ring` is the default and what `Button` shows while loading. `track` keeps the whole path visible,
which reads calmer on a large surface. `dots` suit inline and conversational waits, `bars` a media
or data refresh, and `spokes` a system-level wait. `glow` is the indigo spin for a full-page wait.

### Sizes

Five diameters, from 14px to 32px. `sm` matches body text, `md` sits beside a heading.

### Tones and the glow variant

`current` inherits the surrounding colour, which is what a button needs. The `glow` variant is the
indigo spin used on a full-page wait.

### In context

Inside a control that already reports itself busy, the spinner stays decorative. Where it is the
only sign of progress, the surrounding region carries the live announcement.

## Right-to-left

The spinner is radially symmetric, so it does not mirror. Its rotation direction is the same in both
locales — a clockwise spinner reads as "working" everywhere and is not a directional cue.

Spacing around it uses logical properties, so `ms-2` puts a gap on the correct side in both
directions.

## Composition

`Button` renders a spinner itself when `loading` is set, so you rarely place one there by hand:

```tsx
<Button loading>در حال ارسال</Button>
```

Use `Spinner` directly for inline waits — a list fetching more rows, a panel refreshing — and pair
it with a region that owns the announcement:

```tsx
<p role="status" className="flex items-center gap-2">
  <Spinner size="sm" />
  در حال بارگذاری نظرات…
</p>
```

For a first load of structured content, prefer [`Skeleton`](./skeleton): it holds the shape of what
is coming, so the layout does not jump when the content lands.

## Accessibility

**The spinner is decorative by default.** It renders `aria-hidden`, because the common case is
inside a `Button` that already sets `aria-busy` — announcing both would read the state twice.

Set `labelled` (or pass `label`) when the spinner is the only thing reporting progress. It then
renders `role="status"` with an accessible name from the dictionary's `busy` entry.

| Property        | Decorative (default) | Labelled          |
| --------------- | -------------------- | ----------------- |
| `aria-hidden`   | `true`               | absent            |
| `role`          | absent               | `status`          |
| Accessible name | none                 | `label` or `busy` |

A spinner that can fail must resolve into an explicit error state. Never leave one running forever.

Under `prefers-reduced-motion` the token layer's `base.css` shortens every animation to a single
near-instant cycle, so each variant settles into a still frame instead of moving.

## Theming

| Token                     | Used for                                  |
| ------------------------- | ----------------------------------------- |
| `--color-primary`         | The `primary` tone                        |
| `--color-gray-400`        | The `muted` tone                          |
| `--animate-spin`          | The `ring` and `track` rotation           |
| `--animate-spin-glow`     | The `glow` variant's rotation             |
| `--animate-spinner-dot`   | Each dot's pulse in the `dots` variant    |
| `--animate-spinner-bar`   | Each bar's rise and fall in `bars`        |
| `--animate-spinner-spoke` | Each spoke's fade in the `spokes` variant |

Every variant except `glow` draws with `currentColor`, so it takes the colour of whatever contains it —
override with a text colour rather than a spinner prop.

## Do and don't

- **Do** leave the spinner decorative inside a control that already announces itself busy.
- **Do** use `tone="current"` inside buttons and links so it follows the label colour.
- **Do** pick one variant for a product and keep to it; a screen that spins three different ways
  reads as three different kinds of wait.
- **Don't** show a bare spinner for a first page load where the shape of the content is known —
  use [`Skeleton`](./skeleton).
- **Don't** use a spinner for progress you can measure. [`Progress`](./progress) tells the reader
  how much is left; a spinner cannot.
