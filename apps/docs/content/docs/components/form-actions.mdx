## Anatomy

| Part | Slot                            | Notes                                             |
| ---- | ------------------------------- | ------------------------------------------------- |
| Root | `data-slot="form-actions"`      | `justify-between` with a hint, else `justify-end` |
| Hint | `data-slot="form-actions-hint"` | Muted explanatory text                            |

## Examples

### Alignment

With a hint the row splits, hint at the inline start and actions at the end. `align="end"` keeps the
actions alone at the end, which suits a cancel-and-submit pair.

<ComponentPreview name="form-actions/alignment" />

## Right-to-left

The hint sits at the inline start and the actions at the inline end, so the submit button stays
where the reading direction expects it.

## Composition

- Pass the submit [Button](./button) (and any secondary action) as children.
- `align` overrides the automatic choice when you want actions alone on the end with a hint above.

## Accessibility

- Keep the hint as real text, not a tooltip: rules such as "comments are reviewed before publishing"
  must be readable before submitting.
- The submit button should show its pending state while the form is in flight.

## Do and don't

- **Do** keep one primary action per form.
- **Don't** hide the submit button behind a disabled state without explaining why.
