## Anatomy

| Part        | Slot                             | Notes                                                                            |
| ----------- | -------------------------------- | -------------------------------------------------------------------------------- |
| Overlay     | `data-slot="dialog-overlay"`     | `bg-black/50` with a blur, on the `--z-modal` layer                              |
| Content     | `data-slot="dialog-content"`     | `role="dialog"`; `rounded-3xl`, `shadow-modal`, up to 90% of the viewport height |
| Close       | `data-slot="dialog-close"`       | Corner button at the inline end                                                  |
| Header      | `data-slot="dialog-header"`      | Holds the title and description                                                  |
| Title       | `data-slot="dialog-title"`       | The dialog's accessible name                                                     |
| Description | `data-slot="dialog-description"` | Announced with the title                                                         |
| Body        | `data-slot="dialog-body"`        | Scrolls when the content is taller than the panel                                |
| Footer      | `data-slot="dialog-footer"`      | Actions at the inline end                                                        |

## Sizes

`size` sets the panel width: `sm` for short messages, `md` (default) for forms, `lg` for rich
content. On narrow screens the panel keeps a 1rem margin on each side.

## Examples

### Sizes

`sm` is for short confirmations, `md` — the default — for forms, and `lg` for rich content such as
a preview. The panel never grows past `90vh`; its body scrolls instead.

### Controlled

To open a dialog from code, a menu item or a keyboard shortcut, leave out `DialogTrigger` and control
it: `open` and `onOpenChange` go on **`Dialog`**, the root. `DialogContent` is the panel and doesn't
know whether it is open; props it doesn't recognise are passed on to the panel element, so a
controlled `open` put there silently does nothing.

```tsx
const [open, setOpen] = useState(false);

<Dialog open={open} onOpenChange={setOpen}>
  <DialogContent>…</DialogContent>
</Dialog>;
```

Closing returns focus to whatever had it when the dialog opened, trigger or not. A dialog opened
from a [DropdownMenu](./dropdown-menu) or [ContextMenu](./context-menu) item returns focus to the
menu's trigger or area, because the item itself is gone by then.

### Mandatory dialogs

A dialog the user has to answer, such as a consent or onboarding gate, drops every way of
dismissing it: `showClose={false}` removes the close button, and calling `event.preventDefault()` in
`onEscapeKeyDown` and `onInteractOutside` keeps <kbd>Escape</kbd> and a click on the scrim from
closing it. Pass `open` without `onOpenChange`, so only your own action closes it.

```tsx
<Dialog open={!accepted}>
  <DialogContent
    showClose={false}
    onEscapeKeyDown={(event) => event.preventDefault()}
    onInteractOutside={(event) => event.preventDefault()}
  >
    …<Button onClick={accept}>ادامه</Button>
  </DialogContent>
</Dialog>
```

The focus trap still holds, so the page behind stays unreachable until the dialog is answered. Keep
the way forward obvious and always enabled once its condition is met; a gate with no exit is a trap.

## Right-to-left

The panel is centred with logical insets, the close button sits at the inline end, and footer
actions align to the inline end, so everything mirrors with `AveroProvider`. While a dialog is open,
`@averoui/tokens/base.css` keeps the page from shifting sideways when its scrollbar is hidden, in
both directions, and reserves nothing on a page that had no scrollbar to begin with.

## Composition

- Wrap buttons in `DialogClose asChild` to close the dialog from the footer.
- Use `DialogTrigger asChild` with a [`Button`](./button), or control `open` and `onOpenChange` on
  `Dialog` yourself (see [Controlled](#controlled)).
- To confirm an action, use [ConfirmDialog](./confirm-dialog). For side panels, use
  [Drawer](./drawer).

## Accessibility

| Key                                                | Action                                       |
| -------------------------------------------------- | -------------------------------------------- |
| <kbd>Enter</kbd> / <kbd>Space</kbd>                | On the trigger, opens the dialog             |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves through the dialog; focus stays inside |
| <kbd>Escape</kbd>                                  | Closes the dialog                            |

- Opening moves focus to the first focusable element in the content; closing returns it to the
  element that had focus when the dialog opened — the trigger, or the button, menu or shortcut
  target that opened it from code. The page behind is inert and doesn't scroll.
- A [mandatory dialog](#mandatory-dialogs) ignores <kbd>Escape</kbd> and clicks outside; it must
  offer its own way forward.
- Every dialog needs a `DialogTitle`. Without a `DialogDescription`, pass
  `aria-describedby={undefined}` to `DialogContent`.

## Do and don't

- **Do** keep dialogs short and focused on one task.
- **Don't** open a dialog from inside another dialog.
- **Don't** make a dialog mandatory unless the user truly cannot continue without answering it.
