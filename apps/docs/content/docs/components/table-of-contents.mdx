## Anatomy

| Part       | Slot                            | Notes                                                     |
| ---------- | ------------------------------- | --------------------------------------------------------- |
| Root       | `data-slot="table-of-contents"` | White card with a title and a list icon                   |
| Navigation | —                               | A `<nav>` labelled by the title                           |
| Entry      | —                               | An `#id` link; the current one has an indigo start border |

## Examples

Level-3 entries render smaller as sub-items. With `spy` (on by default), the entry whose heading is at the top of the viewport is highlighted while scrolling.

### Levels and controlled state

Level 3 entries render as indented sub-items. Pass `activeId` with `spy={false}` when the page owns
the highlight, such as a route-driven list.

<ComponentPreview name="table-of-contents/levels" />

## Right-to-left

The active border sits at the inline start, on the right in RTL.

## Composition

- Give every heading an `id` and pass the same ids in `items`.
- Place it in a sticky aside, e.g. `sticky top-28`, which is what [ArticleLayout](./layouts) uses.

## Accessibility

| Key              | Action                    |
| ---------------- | ------------------------- |
| <kbd>Tab</kbd>   | Moves through the entries |
| <kbd>Enter</kbd> | Jumps to the heading      |

- Entries are real links, so they work without JavaScript; the current entry has `aria-current="location"`.

## Theming

Uses `indigo-500` / `indigo-600` for the current entry.

## Do and don't

- **Do** include only h2 and h3 headings; deeper levels make the list hard to scan.
