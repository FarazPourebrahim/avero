## Examples

### Variants

`outline` is the default and matches [Input](./input), [Select](./select) and the other form
controls, so a textarea sits in a form without looking like a different family. `soft` is the gray
comment box, which turns white while you type, and `slate` the bordered one. All three share the
same 2px outline, the `blue-400` focus outline with its `blue-100` halo, and the red invalid state.

<ComponentPreview name="textarea/variants" />

### Resizing

The box is fixed by default, so a form's rhythm holds. `resize="vertical"` lets a reader drag it
taller for a long answer.

## Right-to-left

The box, its placeholder and the resize handle all follow the document direction.

## Composition

- `outline` is white with a 2px gray-300 outline and 12px corners; `soft` has a gray ground; `slate` is
  white with a slate border.
- Resizing is off by default; pass `resize="vertical"` when a long answer is expected.

## Accessibility

- Give it a label, and pair it with an error message referenced by `aria-describedby`.
- Set `aria-invalid` while validation fails; the border and focus ring turn red.

## Theming

| Token               | Used by                                         |
| ------------------- | ----------------------------------------------- |
| `--color-gray-300`  | `outline` border                                |
| `--color-blue-400`  | `outline` Focus outline, with a `blue-100` halo |
| `--color-gray-50`   | `soft` ground, white while focused              |
| `--color-gray-200`  | `soft` outline (`gray-300` on hover)            |
| `--color-slate-200` | `slate` outline (`slate-300` on hover)          |

## Do and don't

- **Do** state the moderation rule next to the submit button with [FormActions](./form-actions).
- **Don't** grow the box automatically while typing; a fixed height keeps the form from jumping.
