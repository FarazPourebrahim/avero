```

import { EditorToolbar, RichTextEditor } from "@avero/editor";
```

## Anatomy

| Part            | Slot                                   | Notes                                                  |
| --------------- | -------------------------------------- | ------------------------------------------------------ |
| Root            | `data-slot="rich-text-editor"`         | Carries `.avero-editor-content`; `data-editable` state |
| Surface         | `.tiptap`                              | Tiptap's contenteditable, styled by `rich-content.css` |
| Toolbar         | `data-slot="editor-toolbar"`           | `role="toolbar"`, named by `editorToolbar`             |
| Toolbar button  | `data-slot="editor-toolbar-button"`    | `aria-pressed` on formatting toggles                   |
| Toolbar divider | `data-slot="editor-toolbar-separator"` | Between the four button groups                         |

## Toolbar

`EditorToolbar` is a separate component, so a page can place it anywhere or leave it out. Keep the
editor from `onReady` in state and pass it in:

```tsx
function CourseDescription() {
  const [editor, setEditor] = useState<Editor | null>(null);

  return (
    <>
      <EditorToolbar editor={editor} />
      <RichTextEditor onReady={setEditor} />
    </>
  );
}
```

It has four groups: bold, italic, underline and strikethrough; heading, subheading, quote and code
block; bulleted and numbered lists; undo and redo. Every button is disabled until the editor exists
and while it is read-only; undo and redo are also disabled when there is nothing to undo or redo.

Tiptap's shortcuts work with or without it, e.g. <kbd>Ctrl</kbd> + <kbd>B</kbd> for bold.

## Styles

The editor does **not** ship its own CSS. Its prose styles live in `@avero/tokens/rich-content.css`
under `.avero-editor-content`, the same stylesheet that styles rendered articles — so what an author
types matches what a reader sees:

```css
@import "@avero/tokens/rich-content.css";
```

## Composition

- The editor is **uncontrolled**: `defaultValue` seeds the document, and later changes to it are
  ignored. Read the current HTML from `onChange`.
- `onReady` hands you the Tiptap `Editor`, which is where a toolbar issues commands from.
- Extensions are `StarterKit` (headings, lists, bold, italic, underline, strike, code, code blocks,
  blockquote, horizontal rules, links), `TableKit`, `Image` and `Placeholder` — exactly the set the
  prose stylesheet has rules for.

## Sanitization

Editor output is plain HTML and is meant to be rendered back through
[RichContent](./rich-content), which sanitizes on every render. The round trip is covered by a test:
every tag in `richContentAllowList` survives it, so allowed formatting is never silently lost.

## Accessibility

- The editing surface is a `role="textbox"` with `aria-multiline="true"` and an accessible name from
  the `editorLabel` dictionary entry (override it with `label`).
- The placeholder comes from `editorPlaceholder` and is drawn with `::before`, so it never becomes
  part of the document's text.
- Direction follows `AveroProvider`, so the surface reads correctly in both `rtl` and `ltr`.

The toolbar follows the WAI-ARIA toolbar pattern:

| Key                                 | Action                                                      |
| ----------------------------------- | ----------------------------------------------------------- |
| <kbd>Tab</kbd>                      | Moves into the toolbar, to the last focused button, and out |
| <kbd>←</kbd> / <kbd>→</kbd>         | Moves between buttons, following the reading direction      |
| <kbd>Home</kbd> / <kbd>End</kbd>    | First or last available button                              |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Applies the focused button's formatting                     |

- Each button is named from the dictionary (`editorBold`, `editorHeading`, …), and formatting
  toggles report whether the selection has that formatting with `aria-pressed`.
- Disabled buttons are skipped by the arrow keys.
- Icons for lists, quotes and undo/redo mirror in right-to-left layouts.

## Do and don't

- **Do** render stored output through `RichContent` rather than injecting it yourself.
- **Don't** import `@tiptap/*` in the core package; the editor stays optional by design.
