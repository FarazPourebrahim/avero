## Anatomy

| Part      | Slot                               | Notes                         |
| --------- | ---------------------------------- | ----------------------------- |
| Root      | `data-slot="site-shell"`           | `flex flex-col gap-y-10`      |
| Skip link | `data-slot="site-shell-skip-link"` | Visually hidden until focused |

## Examples

### A whole page

The shell stacks header, page content and footer, and puts the skip link ahead of them. The content
supplies the `main` landmark, either through a layout template or a `Container as="main"`.

<ComponentPreview name="site-shell/page" />

## Right-to-left

The skip link anchors to the inline start when focused, so it appears on the correct side in both
directions.

## Composition

- `header` and `footer` are slots: pass [SiteHeader](./site-header) and [SiteFooter](./site-footer),
  wired to your own routing.
- The children supply the `main` landmark — usually one of the [layout templates](./layouts). Give
  that element the id the skip link targets (`main-content` by default).

## Accessibility

- The skip link is the first focusable element on the page, which is what makes keyboard-only
  navigation past the header possible.
- Together with the header, layout and footer, the page then exposes the full landmark set:
  `banner`, `navigation`, `main` and `contentinfo`.
- Set `mainId` when your main element uses a different id; a skip link pointing at nothing is worse
  than none.

## Do and don't

- **Do** keep the skip link enabled in production.
- **Don't** render two `main` elements inside one shell.
