## Anatomy

| Part | Slot                       | Notes                                          |
| ---- | -------------------------- | ---------------------------------------------- |
| Root | `data-slot="rich-content"` | Carries the prose class for the chosen variant |

The three variants are three separate prose styles: `content` (`.content-area`),
`editor` (`.editor`) and `question` (`.question-rendered-content`). They are exclusive — each
variant carries its own typography.

## Right-to-left

The prose layer uses logical properties throughout: list indents are `ps-*`, the blockquote border
is `border-s-*`, and headings and cells align to the inline start.

## Composition

- Sanitizing happens on every render, in the browser and during SSR — there is no unsafe mode.
- `sanitize` swaps in your own function when you need a different allowlist. It **must** return safe
  HTML; returning the input unchanged reintroduces XSS.
- `sanitizeHtml` and `richContentAllowList` are exported if you want to sanitize before storing.

## Accessibility

- The rendered HTML keeps its own semantics, so headings, lists and tables are announced normally.
- Heading levels come from the stored content; start articles at `h2` so the page keeps one `h1`.
- Links that open a new tab get `rel="noopener noreferrer"` added during sanitizing.

## Theming

| Token                | Used by               |
| -------------------- | --------------------- |
| `--color-indigo-500` | Blockquote border     |
| `--leading-prose`    | List item line height |

## Do and don't

- **Do** pass untrusted HTML straight in; that is what this component is for.
- **Don't** use `dangerouslySetInnerHTML` anywhere else in your app.
